# Ambis Copenhagen

Hadiah ulang tahun dengan pembuka Gargantua, lalu lima bab: **Hari lahirmu → Bunga & doa → Bait untukmu → Tiup lilin → Surat untukmu**. Surat menjadi penutup cerita. Warna ivory, cokelat hangat, dan cahaya keemasan. Vanilla JavaScript, CSS, dan WebGL dengan fallback Canvas 2D; tanpa framework runtime, backend, atau video animasi besar.

[Arsip chat yang tersedia dan serah terima ke chat baru](docs/chat-archive/2026-10-28/README.md) — transkrip Markdown/JSON, referensi lampiran, riwayat implementasi, dan paket ZIP. Batas kelengkapan arsip dijelaskan di dalamnya.

## Menjalankan

Node.js 22.12+ atau 24 LTS dan npm:

```sh
npm ci
npm run dev
```

Buka alamat yang ditampilkan terminal. Build: `npm run build` menghasilkan `dist/`. Uji hasil build: `npm run preview`. Deploy `dist/` ke hosting statis HTTPS. Untuk hosting subpath gunakan `npm run build -- --base=/Sistem-BTD/`; path media dari konten mengikuti base tersebut.

## Mengisi hadiah dari kode

Semua konten permanen diatur di **src/content.js**. Editor unggahan dan penyimpanan isian browser sudah dihapus dari aplikasi; konten yang dideploy menjadi sumber yang sama untuk semua perangkat.

1. Masukkan sampai **200 foto Gargantua** ke **public/photos/orbit/**. JPG/JPEG/PNG/WebP akan didaftarkan otomatis saat dev/build, dengan urutan nama alami. Untuk urutan manual, isi `photoConfig.orbit` di `src/content.js`.
2. Untuk foto ucapan, puisi, dan surat, masukkan file bernama slot ke **public/photos/story/** (`portrait.jpg`, `hero.webp`, `poem0.webp`, dan seterusnya), atau atur `photoConfig.story`. Identitas **209 slot** tetap sama: 9 slot cerita dan 200 `orbit01`–`orbit200`.
3. Isi `recipient`, `sender`, `birthday`, `poems`, `letter`, dan `letterPhotos` di `src/content.js`. Tanggal kosong tetap tidak memunculkan tanggal fiktif. Doa/kutipan/sumber tetap di `src/quotes.js`.
4. Musik tetap **Country — Koshun Nakao**, dengan file **public/music/koshun-nakao-country-intro-cut.mp3** yang sama. Potongan pengantar, kualitas file, loop, volume awal, autoplay dan fallback ketukan pertama dipertahankan. Untuk mengganti lagu, masukkan file ke `public/music/` dan ubah `tracks[0].src`.
5. Jalankan `npm run build`, lalu deploy `dist/`. Plugin Vite otomatis membuat daftar foto dan memeriksa path media sebelum dev/build, termasuk bila hosting memanggil `vite build` langsung. File yang hilang, daftar duplikat, atau pilihan lebih dari 200 foto orbit dilaporkan sebelum deploy.

**[Panduan lengkap, contoh pengisian, dan tabel slot foto](docs/content-from-code.md).** Foto bawaan tetap kosong sampai file milikmu dimasukkan. Data IndexedDB lama tidak dibaca dan tidak dihapus; file asli perlu dimasukkan ke repo untuk hadiah permanen.

## Alur interaksi

- **Pembuka:** ketuk Buka semesta kita. Countdown singkat, lalu seluruh ucapan hilang selama zoom. Setelah kamera selesai, gerak orbit melambat dan ucapan muncul. Perjalanan dapat dilewati. Tidak ada dialog pembuka.
- **Cerita:** navigasi memakai benda pengantar: rangkaian bunga menuju doa, catatan kertas menuju puisi, lilin menuju harapan, lalu amplop bersegel menuju surat. Ketuk benda atau ajakannya; benda terangkat dan memudar selama 230 ms, disusul dissolve bab 520 ms. Tombol kembali dan hitungan bab tetap tersedia. **Halaman** di header membuka daftar lima bab, dengan Escape dan pengembalian fokus keyboard. Memilih bab yang sedang dibaca menutup daftar tanpa mengulang isi. Adegan bertumpang tindih sejenak untuk transisi yang halus. Puisi memiliki penanda untuk langsung memilih bait; pergantian membaurkan teks dan foto utama tanpa menghilangkan hiasan pendamping; surat mengalir sebagai satu bacaan berbait yang digulir. Doa memakai kebun interaktif: sentuh bunga Bahagia, Bertumbuh, atau Dicintai dalam urutan bebas; doanya muncul dan tetap terkumpul bersama. Setelah bunga pertama dibuka, pilihan bunga kecil tetap tersedia di atas area baca; doa berikutnya bisa dibuka langsung tanpa kembali ke bunga besar. Kutipan sastra, terjemahan, dan sumber bisa dibuka pada lipatan masing-masing doa. Konten tidak berganti otomatis ketika sedang dibaca. Header, area bacaan, dan navigasi menempati baris terpisah supaya foto puisi dan narasi doa tidak tertutup saat scroll. Narasi doa berukuran minimal 16 px. Mawar, tulip, dan anemone memakai ilustrasi transparan WebP yang berbeda (total sekitar 193 KB), dengan gerak mekar/kelopak yang mengikuti pengaturan reduced motion.
- **Surat:** segel dan lipatan amplop terbuka, lalu seluruh bait hadir dalam satu bacaan. Di laptop, kata-kata di kiri ditemani foto yang menetap di kanan; saat bait berikutnya mencapai area baca, fotonya berganti lewat dissolve dan zoom lembut. Di HP, foto menjadi pengiring kecil yang menetap di atas teks. Tidak ada tombol pindah halaman atau scroll yang dikunci. Di akhir tanda tangan tersedia pilihan melipat surat atau menyentuh bintang kristal untuk membaca cerita dari awal. Bintang menunggu di akhir bacaan; surat tetap menjadi bab penutup. Foto mengikuti posisi scroll saat maju maupun mundur; reduced motion mengganti foto langsung. `letter[]` di `src/content.js` berisi bait-baitnya, dan `letterPhotos[]` menentukan slot foto setiap bait (bawaan: `hero`, `moment0`, `moment1`, `moment3`, yaitu Foto surat serta Kenangan 01, 02, 04 pada pemetaan foto). Identitas slot foto tetap dipakai, tanpa menambah foto wajib. Foto bab berikutnya dan seluruh foto puisi disiapkan sebelum dibaca; animasi memakai CSS dan pembacaan scroll dijadwalkan hanya saat dibutuhkan, tanpa library tambahan.
- **Lilin:** layar khusus dengan kue besar → Aku siap buat harapan → Tiup lilinnya → ucapan perayaan. Tidak memerlukan mikrofon atau meniup layar. Bisa diulang. Setelah perayaan, amplop **Masih ada suratku** muncul bersama ucapan untuk membuka bab penutup. Amplop di navigasi bawah disembunyikan saat itu agar hanya ada satu ajakan utama.
- **Aksesibilitas:** fokus keyboard, `inert` pada bab yang tidak aktif, ukuran tombol utama minimal 48 px, reduced motion, autoplay musik mengikuti izin browser dengan fallback ketukan pertama dan volume perangkat. Layar sangat pendek dapat menggulir bab aktif agar isi tetap terbaca. Canvas berhenti ketika tak terlihat/tab tersembunyi; DPR maksimal 2 (dibatasi 3840×2160 pixel) dan 30 fps. Reduced motion menghentikan gerak orbit.

Ornamen mawar dusty rose, mawar ivory, dan baby’s breath memakai satu ilustrasi transparan hasil image generation di `public/art/romantic-roses.webp` (512×768, sekitar 90 KB). Aset ini dipakai ulang pada kolase kenangan, puisi, surat, dan benda pengantar. Bunga dimuat saat diperlukan, mengikuti transisi adegan, dan tidak menangkap klik atau ikut terganti ketika foto diunggah.

```

```

Tidak membutuhkan kredensial.

## Gargantua: gambar detail dan kamera

`public/art/gargantua.webp` adalah rekonstruksi gambar 1672×941 berdasarkan referensi Gargantua yang dikirim pengguna. `gargantua-detail.webp` adalah rekonstruksi close-up dari bagian kanan cakram untuk detail saat mendekat. Keduanya disiapkan dengan image generation/editing dari referensi, bukan diklaim sebagai still film asli atau hasil simulasi relativitas. Encoding WebP mempertahankan dimensi, total sekitar 756 KB. Tidak ada video atau engine WebGL tambahan.

`src/universe-camera.js` menyimpan **32.768 keping foto**, radius, fase awal, ketebalan cakram, dan lintasan kamera 12,2 detik. Foto yang dikonfigurasi diulang pada keping-keping tersebut; angka ini bukan jumlah file foto yang perlu disediakan. Orbit bagian dalam bergerak lebih cepat daripada bagian luar. Kecepatan sudut acuan 0,065 radian/detik dipakai bersama oleh foto, halo dan aliran tekstur (sekitar 43% lebih pelan dari revisi sebelumnya), supaya gerak jauh terasa tenang dan tetap menyatu. Kamera mendekati sisi depan annulus dengan perspektif dan parallax, dengan pembesaran yang bertahap dan kecepatan nol di kedua ujung. Pembuka mengikuti lintasan zoom semula; setelah 35% perjalanan, pembesaran berangsur menyesuaikan sampai close-up yang lebih intim. Kamera berakhir lebih dekat daripada tampilan lebar sebelumnya, sedikit di atas aliran sisi depan supaya lapisan keping kecil tetap terlihat di belakang foto dekat. Radius tidak dibagi menjadi barisan, dan variasi ketinggian membuat keping tersebar naik-turun. Mayoritas keping berukuran kecil; foto besar lebih jarang dengan batas dasar 190 px atau 36% lebar layar. Saat mendekati akhir, foto utama dan batas ukurannya membesar bertahap 18%, sampai sekitar 224 px atau 42,5% lebar layar, dengan jarak komposisi yang mengikuti ukuran baru. Radius dan fase keping tetap mengikuti orbit yang sama; proyeksi sisi belakang dilengkungkan secara optik mengikuti halo. Ucapan tetap tersembunyi sepanjang gerakan. Bagian tengah menyediakan sekitar empat detik untuk melihat banyak foto: waktu kamera melambat secara bertahap tanpa berhenti, orbit tetap bergerak, warna foto kecil lebih cepat terbaca, dan cahaya plasma sedikit meredup agar tidak menutupi gambar. Bagian tengah kini memakai **Crystal Pin**: bingkai kristal dengan bevel bersegi, pantulan putih, pembiasan lingkungan ringan, dan titik asal yang mengikuti orbit. Ujung pin mengikuti permukaan terang cakram depan dan bingkainya berdiri di atas aliran cahaya, dengan radius, fase, dan kedalaman sumber tetap. Foto di lengkungan belakang semakin memudar ketika naik; foto depan mendapat prioritas ruang. Anggaran seleksi tetap 90 foto di HP atau 160 di laptop, termasuk foto yang samar. Pada pengujian bergerak dengan 200 unggahan, jumlah foto jelas rata-rata sekitar 12 di HP 320 px, 16 di HP 390 px, dan 26 di laptop 1280 px. Dua pin paling besar dapat tampil bersama di HP, tujuh di laptop; selebihnya berukuran menengah/kecil sesuai perspektif. Batas foto biasa 64/92 px dan sumber utama 94/138 px untuk HP/laptop. Ribuan keping paling jauh tetap menjadi filamen cahaya. Lapisan thumbnail transparan yang memenuhi seluruh cakram tetap dihapus.

Seleksi memakai satu populasi orbit, dengan pembagian ruang untuk tiga bagian cakram, rasio asli, serta identitas foto yang tetap. Sisi belakang tetap hadir selama slomo dengan peredupan yang meningkat mengikuti tinggi lengkungan. Satu bagian bawah dari ketebalan cakram dibengkokkan ke lengkungan optik bawah; masing-masing sumber hanya digambar sekali, dengan arah putaran bawah yang mengikuti aliran cahaya. Jalur optik ini berbaur halus selama bagian tengah dan kembali ke jalur pembuka/ending semula. Peredupan jarak tetap dipertahankan, dengan foto belakang yang semakin samar agar fokus berada pada pin di depan.

Pemeriksaan jarak memperhitungkan posisi sekarang dan prediksi gerak kamera sekaligus orbit. Ruang foto yang sedang memudar ditahan agar tidak ditumpuk foto baru. Koleksi yang mencukupi memakai foto berbeda bersamaan; prioritas untuk foto baru juga memperhitungkan lama tampilnya setiap sumber agar penggunaan unggahan lebih merata. Khusus ending, identitas foto tetap dipesan sampai kartu lamanya selesai memudar, termasuk ketika sudah keluar dari pilihan target. Foto baru mengambil sumber lain sehingga satu foto tidak muncul bersamaan dengan salinannya yang sedang menghilang. Kedatangan dan kepergian memakai fade, identitas gambar tidak diganti di tengah orbit. Foto dekat mendapat penajaman tepi terbatas pada tile sendiri dan sedikit pantulan cahaya hangat. Canvas menggunakan thumbnail sumber tanpa membuat lapisan versi buram. Seleksi yang sama berlanjut ke ending; jumlah, ukuran, dan jarak berangsur kembali ke komposisi intim semula. Jalur kamera, kecepatan rotasi, dan pengujian kedalaman horizon dipertahankan. Tambahan 3,6 detik ditempatkan lebih awal di tengah ketika pusat Gargantua masih terlihat; pembuka dan komposisi akhir tetap memakai lintasan yang sama. Reduced motion melewati fase ini, dan tombol lewati tetap tersedia.

`src/universe-gpu.js` menggunakan shader WebGL kecil dan satu buffer orbit yang tetap. Dari jauh, keping tampak seperti filamen cahaya keemasan. Seiring ukuran proyeksinya membesar, foto menjadi terlihat; kemunculannya mengikuti ukuran masing-masing keping, bukan pergantian latar pada waktu tertentu. Referensi HD menyediakan detail cahaya. `src/accretion-lens.js` membengkokkan proyeksi sisi belakang dari populasi orbit yang sama ke lengkungan atas dan, selama slomo, lengkungan bawah: satu foto tidak digambar lagi sebagai salinan pada ring terpisah. Fase, radius spiral, identitas dan kedalaman sumber tetap dipertahankan. Lengkungan menyambung halus dengan sisi depan dan berkurang ketika kamera mendekati sisi disk. Persamaan proyeksi dan arah singgung dipakai oleh WebGL maupun Canvas. Aliran tekstur halo memakai arah dan laju angular orbit yang sama; foto mengambil pencahayaan dari luminansi lokal gambar HD sehingga bagian terang menjadi amber dan bagian jauh/gelap menyatu dengan debu. Canvas membaca peta cahaya kecil sekali saat aset dimuat. Foto tetap mengorbit pelan setelah kamera sampai. `src/orbit-composition.js` mengatur close-up tanpa memindahkan posisi orbit: ribuan keping kecil mengisi kedalaman, sementara pada ending maksimal 10 foto utama di HP atau 16 di desktop diberi jarak, variasi rasio asli, dan ruang di sekitar ucapan. Pada ending, foto utama dipilih dari sisi orbit yang menghadap kamera dan memudar saat memasuki sisi belakang. Selama slomo, foto belakang tetap mengikuti proyeksi optik; koordinatnya tidak dibungkus dari tepi kiri ke kanan. Seleksi memperhitungkan gerakan berikutnya dan mempertahankan foto yang sudah terlihat, dengan fade lembut untuk kedatangan/kepergian. Ucapan baru mendapat lapisan kontras lembut setelah perjalanan selesai. Gambar referensi menyediakan detail halo, dengan aliran tekstur terbatas pada daerah bercahaya agar pusat gelap tidak ikut berputar atau berubah bentuk. Ini pendekatan artistik, bukan simulasi relativitas.

Pita terang yang melintang di depan pusat memakai aliran material tersendiri di `src/disk-stream.js`. Tekstur gambar utama dan detail HD bergerak terus ke kiri mengikuti kemiringan pita dan kecepatan foto pada radius acuan. Sambungan tekstur dibaurkan hanya pada tepi periodenya, sehingga aliran tidak bolak-balik, tidak tertahan detail diam, dan tidak habis setelah website dibiarkan terbuka. Canvas menyiapkan tekstur pita dan masker sekali, lalu menggesernya setiap frame. Tes mengambil gerak piksel pita tanpa lapisan foto, termasuk saat close-up, agar foto yang bergerak tidak menyamarkan pita yang diam.

Lengkungan cahaya bawah memakai adveksi sudut yang terus maju dengan laju rotasi foto yang sama. Gambar utama dan tekstur detail HD sama-sama ikut bergerak, sehingga detail yang diam tidak menutupi rotasi. Laju pada bagian optik dalam yang terkompresi dibatasi pada kecepatan acuan agar filamen tetap rapi saat berputar. Masker luminansi membatasi aliran pada filamen bawah; bayangan pusat dan bintang tetap stabil. Canvas memakai lapisan cahaya bergerak dan masker bawah yang disiapkan sekali, dengan kecepatan representatif cakram pada mode fallback.

Rincian Crystal Pin dan pemeriksaannya ada di [docs/crystal-pin.md](docs/crystal-pin.md). `src/photo-surface.js` mengatur orientasi bidang foto: yaw, pitch, roll, dan perspektif berubah pelan mengikuti fase orbit serta waktu simulasi. Shader menggunakan proyeksi balik bidang untuk mengambil tekstur dengan benar saat sudutnya berubah; foto pilihan digambar sebagai quad instanced agar tidak terpotong oleh batas ukuran point sprite perangkat. Normal bidang dan facet memengaruhi pantulan cahaya dari arah Gargantua; kilau dibatasi pada tepian agar detail wajah tetap terbaca. Besar kemiringan berkurang menuju ending. Seluruh bidang, termasuk rasio portrait/landscape ekstrem, dipertahankan di dalam ruang yang dipesan pemilih orbit; identitas foto dan titik asal orbit dipertahankan. Badan pin terangkat di atas titik asalnya. Canvas memproyeksikan facet dari normal yang sama dan memakai dua segitiga untuk foto sumber 320 px, tanpa filter per frame. Ini material bidang foto, bukan penambahan engine 3D atau bloom global.

Atlas foto dibuat sekali ketika unggahan berubah. Ukuran menyesuaikan jumlah foto dan batas tekstur perangkat, dengan anggaran maksimal 8 juta pixel (sekitar 32 MB RGBA). Untuk 209 foto pada perangkat dengan batas tekstur 4096, atlas memakai 2720×2600 pixel. Tile 160×200 mempertahankan lebih banyak detail koleksi penuh daripada tile 128×160 sebelumnya, tetap dalam anggaran 8 juta pixel. Tiap foto diberi padding dan batas UV setengah texel agar baris foto tetangga tidak ikut tersampel. Tekstur baru diuji sebelum identitas dan layout diganti; jika GPU menolak unggahan, resolusi atlas diturunkan dan dicoba ulang tanpa mengubah foto tersimpan. Foto utama yang dekat kamera memakai cache detail terpisah di `src/portrait-textures.js`: maksimal 16 foto pada tile 320×400, dengan tambahan tekstur maksimal sekitar 8 MB RGBA. Foto besar yang baru mendekat mendapat prioritas detail berdasarkan ukuran yang terlihat di layar dan opasitas, sehingga tidak kalah oleh foto kecil yang lebih lama tampil. Hanya slot foto yang berubah diunggah ulang, bukan seluruh atlas setiap frame. Jika perangkat menolak, ukuran detail diturunkan atau foto kembali memakai atlas utama. Penajaman tepi dibatasi agar tidak membentuk halo; kabut dan campuran warna dikurangi bertahap khusus foto dekat, sementara foto jauh tetap lembut dan hangat. Canvas memakai cache penajaman yang juga dibatasi 16 foto. Tidak ada ribuan elemen DOM atau ribuan file gambar. Thumbnail dengan sisi panjang maksimal 320 px didekode maksimal empat bersamaan dan dipakai ulang. Seluruh framing asli dipertahankan; rasio portrait, landscape, dan persegi disimpan bersama identitas foto lalu dipulihkan saat menggambar keping. Warna asli muncul bertahap pada ukuran sekitar 2–28 px, sehingga foto yang mulai terbaca tidak terus tertutup warna plasma keemasan. Penempatan foto memilih gambar berbeda untuk keping yang berdekatan pada beberapa posisi orbit, sekaligus menyeimbangkan pemakaian seluruh koleksi. Pilihan disimpan selama animasi agar foto tidak berganti saat zoom. Jumlah foto unik tetap bergantung pada unggahan; pengulangan masih mungkin ketika banyak keping terlihat. Kamera menunggu penyiapan koleksi sebelum perjalanan. Tanpa foto pribadi, keping berisi bingkai kosong. Browser tanpa WebGL menggunakan 8.192 keping Canvas 2D dan tetap dapat membuka seluruh cerita. Detail close-up dimuat setelah gambar utama; kegagalan aset tidak mengunci hadiah. Render berhenti saat adegan/tab tersembunyi atau reduced motion aktif, dengan batas 30 fps dan resolusi retina sesuai anggaran pixel.

`src/motion.js` menahan frame terakhir sampai opacity/transform disimpan, lalu melepas efek animasi. Bab lama disembunyikan sebelum gayanya dibersihkan. Header, footer, label bab, dan isi memakai satu dissolve 520 ms tanpa salinan kontrol lama, pergeseran, atau pembesaran halaman. Satu bidang latar memudar ke warna bab tujuan; kontrol transparan tidak membentuk lapisan tebal di atas foto. Navigasi terkunci lewat `inert` selama perpindahan, tanpa meredupkan tombol dan membuatnya menyala terlambat. Header dan navigasi memiliki baris tersendiri (64 px dan 100 px pada desktop, 66 px dan 106 px pada HP; laptop pendek memakai 56 px dan 80 px), sementara komposisi foto, amplop, teks, dan lilin menyesuaikan tinggi area baca melalui container units. Konten personal yang panjang tetap bisa digulir dengan scrollbar tipis. Puisi mengganti foto dan teks bersamaan saat transparan. `src/keepsakes.js` dan `src/keepsakes.css` membentuk benda pengantar dari aset bunga yang sudah dipakai, CSS gradient/shadow, dan SVG kecil; tanpa library runtime atau media baru. Animasi benda dilepas setelah navigasi berikutnya terpasang, sehingga benda lama tidak menyala kembali. Reduced motion langsung mengganti bab tanpa gerakan tambahan.

Tes halo memeriksa jalur optik yang berkesinambungan, gerak filamen dari populasi foto belakang pada lengkungan atas, bayangan horizon yang tetap menutup foto belakang, serta orbit depan dan close-up akhir yang tidak berubah. Tes komposisi mengamati lima detik slomo dengan 200 foto berasio campuran, memeriksa jarak, identitas, ukuran terbaca, fade, dan persebaran di tiga bagian cakram. Jalur optik bawah diuji sepanjang satu putaran tanpa perpindahan mendadak; piksel unggahan diperiksa pada lengkungan atas dan bawah. Tes GPU memeriksa kontras di dalam foto dengan atlas 200 unggahan serta foto yang tetap terbaca di area gelap. Tes tambahan membaca frame transisi untuk mendeteksi kilatan halaman lama, memeriksa gerak idle dan bayangan pusat yang stabil, pembekuan reduced motion, orbit spiral masuk dengan kedalaman yang berbeda dan fade sebelum horizon, pembesaran kamera tanpa sentakan di akhir, foto konfigurasi yang benar-benar terlihat pada pixel canvas, orientasi portrait/landscape dan pinggir foto yang tetap utuh, kepadatan latar saat close-up, jarak antar foto utama dan lintasannya selama 450 frame sampai keluar tepi kiri tanpa berbalik, serta fallback tanpa WebGL/aset gambar.

Foto kini mengikuti spiral masuk: kuadrat radius berkurang, sementara kecepatan sudut terintegrasi meningkat ketika mendekati pusat. Foto meredup sebelum radius horizon, lalu partikel hanya diisi kembali di tepi luar saat tak terlihat. Ray/sphere depth test berjalan per pixel pada shader supaya foto di belakang lubang—termasuk ujung bingkainya—tertutup; foto di depan tetap dibedakan berdasarkan kedalaman. Fallback Canvas memakai siluet sphere dan clipping. Pemilihan foto yang terbaca memakai batas 90/160 saat tengah, lalu berangsur kembali ke 8/16 menjelang ending. Khusus ending HP, batas menjadi 10; beberapa foto jarak menengah ikut dipilih untuk mengisi ruang kosong, sementara foto besar, penghindaran tabrakan, dan ruang ucapan tetap dipertahankan. Rotasi ending HP menjadi 1,8× laju ending desktop, dengan percepatan halus setelah progress 0,78; waktu simulasi yang sama menggerakkan foto dan cahaya cakram. Slomo tengah serta laju desktop tetap sama, dan reduced motion tetap menghentikan putaran. Ribuan keping jauh tetap mengisi cakram sebagai cahaya di belakang foto yang terbaca. Ini visualisasi artistik dengan perspektif dan occlusion, bukan simulasi relativitas penuh.

Foto kini mendapat peredupan, penurunan detail, dan transparansi berdasarkan kedalaman kamera. Material orbit dalam mengecil dan mengikuti arah aliran sambil memudar pada radius 0,108–0,190, sebelum radius horizon 0,095. Tepi belakang juga memakai zona pelarutan lembut sebelum pengujian sphere yang tegas, sehingga bingkai tidak tampak terpotong mendadak. Foto sisi depan tetap mengikuti kedalaman sebenarnya. Jalur, identitas, dan jumlah keping orbit dipertahankan.

Di HP, framing pembuka tetap menyisakan tempat untuk ucapan. Setelah tombol pembuka ditekan, kamera bergeser turun dan mendekat sedikit secara halus selama satu detik, bersamaan dengan hilangnya teks dan lapisan gelap pembuka. Gargantua mengisi ruang tengah ketika countdown/perjalanan berlangsung. Pembesaran, durasi perjalanan, dan framing akhir tetap sama; replay mengembalikan framing pembuka dan resize mengikuti ukuran viewport.

Latar Gargantua menyambung sampai tepi layar: tekstur langit dan filamen paling luar diteruskan mengikuti kemiringan cakram, lalu meredup secara bertahap. Tidak ada bidang hitam polos pada batas gambar. Framing kamera dan resolusi gambar pusat tetap sama; sampel ekstensi dibatasi pada 8% tepi sehingga tidak menggandakan lubang hitam. WebGL menghitung ekstensi di shader. Canvas menyiapkan ekstensi sekali saat gambar dimuat, mempertahankan gambar asli di tengah, dan kembali memakai satu gambar saat kamera sudah masuk ke close-up.

Saat zoom masuk ke bagian tengah, kamera mengunci pusat visual Gargantua pada tengah viewport HP maupun laptop. Seluruh tahap foto/slomo (progress 0,16–0,42) memakai sumbu lurus tanpa bidikan ke kanan. Peralihan masuk dan keluar kuncian memakai easing dengan kecepatan serta percepatan nol di batasnya, kemudian menyambung ke komposisi potret akhir. Durasi perjalanan, pembesaran, jalur orbit dan framing ucapan penutup dipertahankan.
